# TAITE（タイテ）

DJ Set Timer & Timetable — 自分の出番まで・セット残り時間をスマホで把握する。

DJイベントのタイムテーブルをリンクで共有し、各自のスマホで現在時刻・セットの残り時間を表示するPWA。タイムテーブルはサーバーに保存し、変更はリンクを開いている全員にリアルタイムで届く。

公開URL: https://taite.pb-worker.workers.dev/

## 仕組み
- 画面（`src/`）と API（`worker/`）を **Cloudflare Workers** 1つで配信する
- タイムテーブル1つにつき **Durable Object** 1つ。保存と、開いている全員への **WebSocket でのリアルタイム配信** を受け持つ
- 編集できるかどうかは「編集用の鍵」で判定する（サーバーには鍵のハッシュだけを保存）。ログインはない
- 作成したタイムテーブルの一覧・出演予定の一覧・最後に受け取った内容は、その端末に保存する（電波が切れても表示とタイマーは続く）

| URL | 誰が使う | できること |
|---|---|---|
| `#/` | 作成者・（アプリに登録した）DJ/一般客 | トップ（タイムテーブルの一覧。右上にリンク・QRコードから追加するスキャンボタンと新規作成のプラスボタン）。スマホは行のスライド、PCはカーソルを乗せて操作（下記）。終わったイベントはグレー。ブラウザでは `?l=<id>,…#/` の形で一覧をURLに載せる |
| `#/new` | 作成者 | 新規作成（入力して Create Timetable で登録） |
| `#/edit/<id>/<key>` | 作成者（他の人に渡さない） | 編集（自動保存）、DJ用・一般用リンクとQRの発行・書き出し、削除 |
| `#/dj/<id>` | DJ | タイムテーブル + 自分のタイマー。リンクで開くとそのイベントだけが見え、トップには戻れない（アプリの一覧から開いた時だけ戻れる） |
| `#/t/<id>` | 一般客 | タイムテーブルのみ（同上） |
| `#v1.…` | — | 以前の形式の共有リンク（タイムテーブルの中身を `#` 以降に圧縮して埋め込んでいた）。閲覧のみで、更新・編集はされない |

## 開発
```bash
npm install
npm run dev:api   # API（Cloudflare Workers をローカルで実行, 8787番）
npm run dev       # 画面（Vite。/api は 8787 に中継）
```

デバッグ: `?now=2026-11-21T21:55` で現在時刻をずらせる。開発サーバーでは `mock.html` で状態別の画面を一覧できる（`?me=` / `?view=` / `?ack=` は開発時のみ有効）。

## 公開
```bash
npx wrangler login   # 初回のみ（Cloudflare アカウントでログイン）
npm run deploy       # ビルドして Cloudflare Workers に公開
```

main へのマージでは Cloudflare に公開されない（GitHub Pages は以前のURLの転送ページだけ）。**先に `npm run deploy` で公開して新しいURLで動作を確認してから、main にマージする**（逆の順だと、以前のURLから転送された先が古い版になる）。

## 機能
- 表示言語: 英語。デザインは全画面共通で「チャコールの地に、罫線で区切った行（左にラベル）」。書体は Barlow（DIN系、数字は等幅）、主な操作ボタンは白。タイマーの数字だけ状態の色で大きく光る。操作はアイコン、ラベルは短い文字
- 画面: スマホ縦・横、折りたたみの外側（細い画面）、内側・タブレット（タイマーとタイムテーブルを左右に並べる）に対応
- 作成画面: タイムテーブルと同じ罫線の行で Event・Date / Sets / Share / Manage に分ける。イベント名・日付・各セット（1行に つまみ・DJ名・開始–終了・削除）。時刻は下から出るホイール（5分刻み）、日付はカレンダーで選ぶ。開始を動かすと長さを保って終了も動く。つまみ（≡）のドラッグで並べ替えると、各セットの長さを保ったまま最初の開始時刻から順に時刻を詰め直す。日付またぎ対応、重なり警告。編集は自動でサーバーに保存するが、日付・時刻・DJ名が欠けている間は保存しない（途中の入力を配信しない）
- 共有: DJ / Public のタブごとにリンクのコピー・Web Share・QRコード（PNGで書き出し）。Manage に編集用リンクと削除
- 画面はタイムテーブルとタイマーの2つ。リンクを開くとタイムテーブルが出て、名前をタップするとそのDJのタイマーへ（選んだDJは端末に保存。主催者がDJ名を直しても同じ枠を自分として追い続ける）
- タイマー画面（スクロールしない固定レイアウト）
  - 上部にイベント名、その下に自分のDJ名（同じ大きさ）
  - 中央の上段に現在時刻（Time）と自分のセット時間（Your Set）を横並び
  - その下に Now Playing（今プレイ中のDJ名）と Next（次のDJ名）。DJ名の横に開始〜終了を小さめに表示
  - その下に出番までの時間 → 残り時間 → 超過時間を大きく表示。状態は Standby（白）→ Cue（10分前、青）→ On Air（緑 → 残り10分 黄 → 5分 橙 → 1分 赤）→ Over
  - 左上に戻るボタン（‹ = タイムテーブルへ）、右上にスリープ防止のアイコン（湯気の立つカップ = 画面を消さない / 湯気なし = オフ。使えない時は押すと理由を表示）
- タイムテーブル画面: 一覧（今プレイ中の時刻は緑）。名前をタップするとそのDJのタイマーへ。タイマーの ‹ や端末の「戻る」でいつでも一覧に戻れる
- 警告: 残り10分 黄 / 5分 橙 / 1分 赤点滅 / 超過 高速点滅（タップで点滅停止。Androidは振動）。動きを減らす設定では点滅せず固定表示
- 画面スリープ防止（Screen Wake Lock API）、オフライン対応（Service Worker）
- 電波なしで開けるのは、その端末で一度開いたタイムテーブルだけ。主催者はDJにリンクを渡したら、本番前に一度開いてもらう（共有画面のDJタブにも注意書きを出す）
- つながっているか25秒ごとに確かめ、応答がなければ電波なしの表示にしてつなぎ直す。画面に戻った時は最新の内容を取り直す
- 役割: 作成者はアプリで作成・管理・リンク発行・本番の表示を行う。DJ・一般客はリンクを開くと、そのイベント専用の画面だけが見え、トップには戻れない（リンクを開いただけでは一覧に入らない）。自分のアプリに登録したい時は、アプリのトップのスキャンボタン（Add from Link or QR Code）から、リンクの貼り付け・QRコードをカメラで読む・QRコードの画像を選ぶ、のどれかで登録する（QRの読み取りは jsQR を使う時だけ読み込む。カメラは https または localhost で、許可が必要）。編集リンクを貼り付けた場合は編集画面を開く
- 一覧の操作（iOS のメールと同じ）
  - スマホ: 行を左へスライドすると Delete（登録しただけのものは Remove）、右へスライドすると Edit・Link（自分が作ったものだけ）。途中で離すとボタンが出たまま止まり、端までスライドしきって離すと、そのまま削除・編集画面へ進む（自分が作ったものの削除は、サーバーからも消えるので確認を出す。Remove はこの端末の一覧から外すだけ）
  - PC（マウス）: 行にカーソルを乗せると、右端に Edit・Link・Delete のボタンが出る
  - Link は DJ用・一般用のリンクとQRコードを表示し、コピー・共有・QRの保存ができる
  - 終わったイベント（最後のセットの終了時刻を過ぎた。内容がまだなければ開催日を過ぎた）はグレー表示
- iPhone では、LINE やメールのリンクはホーム画面のアプリではなく Safari で開く（アプリと Safari は保存場所も別）。iPhone のブラウザでDJ用リンク・編集リンクを開いた時は、アプリで使う方法（リンクをコピーしてアプリのスキャンボタンから登録する／ホーム画面に追加する）をリンクごとに一度だけ案内する
- ホーム画面に追加すると、追加した時のページで開く（DJ用リンクから追加すれば、そのタイムテーブルが開く）。トップから追加した時は、URLに載せた一覧をアプリの起動時（ページを読み込んだ時）に一度だけ取り込む（iPhone はアプリと Safari で保存場所が別のため。編集用の鍵は載せないので、自分が作ったものもアプリでは閲覧のみ）。編集リンクを開いた状態で追加すると鍵つきのURLが起動先になるので、他人や共有の端末では編集リンクから追加しない
- リアルタイム更新で描き直しても、開いている画面・スリープ防止のオン/オフ・一覧のスクロール位置は保つ

## 以前のURLからの移行
以前の公開URL: https://kodai-over.github.io/taite/ は、`redirect/` のページで新しいURLへ転送している（# 以降も引き継ぐ。古いオフライン用の仕組みも片付ける）。

- 端末に保存した内容（選んだDJ名など）はURLごとに別なので、新しいURLでは初回に自分のDJ名を選び直す
- オフライン用の保存も新しいURLで作り直しになる。電波の弱い会場で使う場合は、本番前に一度新しいURLを開いておく
- 以前のURLをホーム画面に追加していた人は、転送先がブラウザで開く。本番前に新しいURLを開き直し、ホーム画面に追加し直す
